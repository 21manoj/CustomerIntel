## 0. The original discussion, recovered from the announcement itself

The session transcripts and memory did not hold the earlier discussion, so it was recovered from the source (web, 2026-09-04): **Google Cloud launched *Gemini Enterprise for Legal* and *Gemini Enterprise for Financial Services* on 2026-08-25** — its first industry-packaged editions (healthcare and life sciences "on the horizon"). Legal launch firms: Cleary, Freshfields, Weil, Williams & Connolly; Financial Services design partner Deutsche Bank, with CME Group, BNY, Citi Wealth, Lloyds, Macquarie. Analysts framed it as "governance matters more than models".

The announcement stresses four areas. These are the inspirations to carry:

| # | Google's emphasis | In their words | Our equivalent | Verdict (details in §1) |
|---|---|---|---|---|
| G1 | **Verifiable grounding with traceable citations for every output.** The FS research agent adds *confidence scores, explicit methodologies, data snapshots for auditing, precise source citations, full data provenance*. | "holds every output to verifiable grounding with traceable citations" | Evidence nodes with verbatim quotes and provenance; `evidence_node_ids` on episodes/phases/arcs; no fallback arcs; `data_origin`-gated "measured" label. | **Data layer done; surface missing** (no read tool/route returns a journey or node); **snapshots missing** (journeys overwritten in place); extraction confidence is LLM self-report. |
| G2 | **Governed control plane**: audit logging, risk dashboard, permissions and ethical walls *inherited from the connected systems*, private data isolation, never used for training. | "a governed control plane … natively enforces security policies" | Scoped API keys per customer; LLM spend ledger (working as of `a5b20a7`); per-tenant queries. | **Partial**: no override audit, no RBAC/SSO, isolation is per-query not centralised; nothing inherits permissions from a source system. |
| G3 | **Domain skills + secure MCP connectors + partner agents.** Skills = *expert-authored, reusable instruction packages that enforce the firm's playbooks and citation rules*; 13+ connectors to systems of record; open third-party agent ecosystem. | "reusable packages of instructions … designed by domain experts" | Taxonomy overlays + role definitions + few-shot examples + KPI catalogs are exactly this layer — expert-authored data, not code, enforced as a tool-schema enum. MCP server + ingest routes are the connector seam. | **Skills: done in shape**; **connectors: seam only** (no source adapters to Zendesk/Gong/Salesforce/Gainsight); **partner agents: none**. |
| G4 | **Human verification before consequential actions** — "practitioner confirmation" before filing or redaction; analyst judgement stays in the loop. | "practitioner review" | Review queue (GET only); `ApprovalRequest` tiers in `approval_queue.py`. | **Missing**: no accept/reject write path, `requires_review` not honoured downstream (low-confidence nodes enter the leading composite at full weight), approval routes never mounted, no audit of overrides. |

The two principles the user named map onto G1: "evidence needs a surface" is the citation/surface half, "all outcomes grounded in data" is the grounding half. G2–G4 are the ones we had *not* been carrying explicitly, and G4 is the weakest.

## 1. Question 1 — are the principles taken care of?

**The data layer is built to these principles; the surfaces, the human loop, and the extraction eval are not.**

| # | Principle | Verdict | Where it is honoured | The gap |
|---|---|---|---|---|
| 1 | Evidence needs a surface | **Partial** | Every OBSERVED node carries the verbatim `quote` as its title and in `properties` (`signal_engine/pipeline.py:256,270`); episodes cite `evidence_node_ids` (`journeys/journey_builder.py:41,103`); the arc cites `supporting_episode_ids`, `alternatives` with what they were missing, `contradicting_evidence` (`journeys/arc_classifier.py:185-196`); phase boundaries cite `trigger_episode_id` (`journey_builder.py:255`); each month of the leading series lists `contributing_episode_ids` (`:324`). | **There is no surface.** The only renderer is the static mock, built from an exported JSON file (`docs/design/mocks/build/build_canvas.py` reads `zenith_journey.json`; no `fetch(` in any mock). The server exposes seven MCP tools (`create_customer`, `upload_csv`, `process_data`, `trigger_wizard`, `submit_signal`, `process_signals`, `configure_signal_engine`) and the `/api/signals/*` ingest/process/review-queue/status routes (`signal_engine/http.py:406-412`) — **no route or tool returns a journey, an episode, or an evidence node**. The citation-enforced story paragraph is design only (`journey-canvas.md` §2; P8). |
| 2 | Outcomes grounded in data | **Done** (data layer) | No fallback arc: `steady` or `unclassified` with a stated reason (`arc_classifier.py:6-12, 198-208`). Wizard A writes no ContextNode/ContextEdge rows (`journeys/wizard_a.py:13-14`; `test_no_synthetic_nodes_or_edges_written`). The extraction vocabulary is a tool-schema enum, so an invented subtype is rejected by the API (`signal_engine/enrichment.py:117-118,135`); anything that slips through is dropped and counted (`:247-248`). A failed extraction is not evidence — the signal stays queued (`pipeline.py:352-358`). The keyword stub is always `requires_review` (`enrichment.py:373`). The backtest labels a result `measured` only when `data_origin` is NULL **and** the caller asserts `--real` (`evals/lead_time_backtest.py` docstring). | The forward-looking block (outlook, likelihood fan, tripwires) is computed in the mock's JavaScript (`journey-canvas-proposal.md` §2.2) — the one part of the story a buyer cares most about is not yet a platform output (P8). |
| 3 | Human in the loop | **Missing** | `GET /api/signals/review-queue` lists `requires_review` rows (`http.py:125-133`, `ingest_api.py:121-139`). `approval_queue.py` has approve/reject routes (`:393,410`) and an `ApprovalRequest` model. | The review queue is **read-only**: no accept / reject / reclassify write path, and **nothing downstream reads `requires_review`** — outside `signal_engine/` it appears only as a column (`models.py:430`). A low-confidence node enters the leading composite (`journey_builder.py:282-285`) and the arc rules with the same weight as a high-confidence one. `approval_queue`'s blueprint is never mounted on the FastMCP server (`server.py` registers only signal routes; `auth_middleware.py` is a `NotImplementedError` placeholder), so it is importable, not reachable. No table records a human override. |
| 4 | Auditability / provenance | **Done** for machine provenance, **Partial** for the rest | Node: `source='observed'`, `source_platform=<source_type>`, `source_event_id=<signal_id>` (`pipeline.py:268-271`); properties carry `classification_basis` (`declared_subtype` / `llm_extraction` / `llm_intent` / `unclassified`), `llm_model_version` (`structured_rule_map` for the rule path, `stub_keyword_v2` for the stub), `confidence`, `requires_review`, `evidence_tier`, `polarity_conflict`, `raw_sentiment_score`, `person_unresolved` (`:251-267`). The signal row keeps `raw_text`, `extractions`, `content_hash`, `source_ref`, `occurred_at` (`signal_engine/models.py:11-36`). Evidence tiers observed / inferred / synthetic in `utils/provenance.py:35-37`. Every LLM call is metered (`enrichment.py:326-329`) into `LLMUsageLog` — a table that exists only as of `a5b20a7` (`models.py:81`: before it "every record_usage silently failed"; a guard-never-fires case, now covered by `TestLLMLedger`). `WizardRun` is an audit row per wizard (`models.py:570`). | No **prompt version** or **taxonomy version** on the node (`taxonomy_base.json` is `"version": "0.1"`; prompt v2 landed in `b474683` but only the model id is stamped) — after the next prompt change, old and new extractions are indistinguishable. Journeys are **upserted in place** (`wizard_a.py:57-69`): there is no record of what the journey said last month, which the scrubber and any "what did we know when" audit require. `ContextNode.confidence` is never set by the pipeline, so the column holds its default `1.0` while the real value sits in `properties.confidence` (`pipeline.py:268-272`; `models.py:264`). |
| 5 | Domain-specific evaluation | **Missing** | 308 tests; `evals/lead_time_backtest.py` with pre-registered thresholds (`PREREGISTERED = {median ≥ 60 d, recall ≥ 0.70, FA ≤ 5/100}`), right-censoring, refutation, evidence label. Taxonomy carries role definitions ("is / not") and few-shot examples per vertical (`taxonomy_base.json`, 17 roles; overlays 105–112 subtypes). | **No extraction eval.** The signal-engine tests mock the LLM (`tests/test_signal_engine_v2.py:187-232`, `fake_llm`). There is no labelled set of communications with gold subtype / role / person, hence no precision, recall, or per-vertical confusion matrix, and no measurement of polarity-conflict rate, unresolved-person rate, or unclassified rate per source (P16 item 8, "coverage stats", is still open). The one eval we have measures *lead time*, which presupposes the extraction is right. |
| 6 | Confidence that means something | **Partial** | Semantics are declared where they are not calibrated: arc `confidence_semantics: 'rule_match_constant'` (`arc_classifier.py:189`), edge `'role_match_heuristic_constant'` (`mcp_server/process_data_pipeline.py:417`), Wizard B interventions "a comparison, not a causal estimate", the forecast fan "prior, not calibrated" in design. Extraction confidence has a stated meaning — explicitness: 1.0 stated / 0.7 strongly implied / 0.5 weakly implied (`enrichment.py:56`), threshold from config. | Extraction confidence is **LLM self-report** and carries no semantics label on the node (should read e.g. `llm_self_report_explicitness`). Nothing is calibrated against outcomes anywhere — by design until a tenant has events, but it should be stated on every number the way the arc does. The `1.0` default on `ContextNode.confidence` (row 4) actively misleads anything that reads the column. |

**Net.** The spine is honest: quotes, citations, no fabrication, no fallback, provenance on every node, thresholds pre-registered. What is missing is everything a *person* touches — a read surface, a review write path, an audit of overrides, and a labelled eval of the extractor. Those four are also the four cheapest items in §2.

|---|---|---|---|---|---|

The first five share one prerequisite: **a read surface over journey v3 and its evidence nodes**. Build it once and #1–#5 become days, not weeks.

## 3. What NOT to build yet

- **Ask AI before the read tools and the narrative block exist** — it would answer from raw tables, which is exactly what P10 forbids.
- **The forecast block as a product output** (P8) before a tenant has real events — the mock's fan is already labelled "prior"; shipping it live invites reading it as a prediction.
- **Dollars per pillar / per-playbook ROI** — no tenant has a calibrated health → retention relationship; exposure-weighted priority is the honest ceiling (`journey-canvas-proposal.md` §4.4).
- **The agentic actuator** before the review write path, real auth, and an override audit — otherwise the first autonomous action has no human record behind it.
- **Community domain intelligence and the GRC fork** — both need real cross-tenant data or a separate product decision.
- **A second extraction model or prompt tuning** before a labelled eval exists — there is nothing to measure improvement against.
